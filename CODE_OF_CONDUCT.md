# Code of Conduct

IronMesh is a small project. We don't have a board, we don't have HR,
we don't have a complaint portal. What we have is a tiny number of
simple rules:

## Rules

1. **Be technically honest.** Don't overclaim. If a feature is beta,
   say beta. If a benchmark was indoor at 5 feet, say so. If your
   code has a known bug, list it.
2. **Assume good faith, extend it twice.** Most "bad" interactions are
   miscommunication. Re-read, ask, then decide.
3. **Credit generously.** If someone's idea landed in the code, say so.
   If someone caught your bug, thank them.
4. **No harassment.** No personal attacks, no dogpiling, no
   discrimination, no targeted slurs. Disagree hard on the code; don't
   make it about the person.
5. **Keep politics out of the code reviews.** The project is
   political enough — it's explicitly about self-sovereign
   infrastructure. But the PR comments are for the PR.

## Enforcement

Violations of rule 4 get a warning. Second violation: removed from
the project. Non-negotiable, no appeals process, because this is a
volunteer-run project and we don't have bandwidth for one.

Everything else — we'll talk about it in the issue thread. Most
disagreements resolve themselves when someone pastes a stacktrace or
a test case.

## Scope

These rules apply to:

- GitHub issues, PRs, discussions on this repo
- Any IRC / Matrix / Discord channel that lists IronMesh as its focus

They don't apply to your private communication, your other projects,
or your life outside the repo. We're not the morality police.

## Who wrote this

The maintainer of IronMesh, who believes most "codes of conduct"
are longer than they need to be and that clarity beats comprehensive
coverage.
